What's under the hood
01
A fixed sequence, not an open-ended agent. Triage → duplicate check → assignment → create runs in a deterministic order using forced single-tool calls at each stage, because ticket routing is a business process with a correct order — this deliberately isn't an autonomous agent loop.
02
Live duplicate detection. Before creating anything, the duplicate-check stage searches existing open tickets in the real backend and only flags a match when it's clearly the same underlying issue.
03
Switchable backend, zero downtime. Settings lets you point the pipeline at a mock store, ClickUp, ServiceNow, or both at once — dual-write fans every create and dedup check out to both systems and merges the results.
04
Credentials never touch disk. API tokens entered in Settings live only for the running session — restarting the app clears them, by design.
